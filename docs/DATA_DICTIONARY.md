# Data dictionary

## Observation import

| Field | Type | Required | Meaning and validation |
|---|---|---:|---|
| `vehicleId` | string | Yes | Must match an existing synthetic vehicle. |
| `parameter` | string | Yes | `engine_coolant_temperature` or `battery_voltage`. |
| `value` | number | Yes | Finite JSON number; numeric strings are rejected. After conversion, screening ranges are -50–180 °C and 0–30 V. These ranges validate interpretability, not vehicle condition. |
| `unit` | string | Yes | Explicit supported temperature or voltage unit. Converted to `°C` or `V`; preview and stored source disclose the conversion. |
| `observedAt` | ISO 8601 string | Yes | Date-time including seconds and explicit timezone (`Z` or `±HH:mm`), optional 1–3 fractional-second digits. Stored as UTC ISO. Invalid dates and timezone-free strings are rejected. |

Each accepted observation receives a database identifier and import timestamp. Rejected payloads and explanations are retained in `import_rejections`. Missing measurements are not inserted and are never replaced with assumed normal values.

## Supported conversions

| Parameter | Accepted input units | Canonical storage unit | Conversion |
|---|---|---|---|
| Coolant temperature | `°C`, `C`, `celsius` | °C | Identity |
| Coolant temperature | `°F`, `F`, `fahrenheit` | °C | (value − 32) × 5/9 |
| Coolant temperature | `K`, `kelvin` | °C | value − 273.15 |
| Battery voltage | `V`, `volt`, `volts` | V | Identity |
| Battery voltage | `mV`, `millivolt`, `millivolts` | V | value / 1000 |

Units are trimmed and matched without case sensitivity. No unit is inferred. Converted values are not rounded before assessment; standard JavaScript floating-point arithmetic applies. Unknown units or cross-parameter units (e.g. mV for temperature) are rejected. Field names and parameter identifiers retain the exact documented schema; manufacturer-specific signal mapping remains future work.

Source value, original unit, original timestamp and formula are retained separately for newly imported observations. Older stored observations lacking source metadata remain available without inventing a source history.

## Main entities and links

| Entity | Purpose | Important links |
|---|---|---|
| `vehicles` | Synthetic fleet or owner vehicle. | Parent of observations, warnings and actions. |
| `observations` | Timestamped measurement. | Belongs to one vehicle. |
| `observation_sources` | Original input value, unit, timestamp and applied conversion. | References one accepted observation; survives database reopen. |
| `warnings` | Rule alert or simulated forecast display item. | Belongs to one vehicle; `source_type` distinguishes origins. |
| `warning_observations` | Supporting evidence junction. | Connects a rule warning to its observation. |
| `forecasts` | Pre-entered simulated forecast input. | Never generated by a trained model. |
| `actions` | User-recorded response. | Must reference the same vehicle and warning. |
| `action_history` | Timestamped status and note. | Retains every action transition. |
| `vehicle_locations` | Synthetic map position for the demonstration. | One optional location per vehicle, labelled and timestamped. It is not live GPS telemetry. |

Allowed action statuses: `planned`, `in progress`, `completed`, `cancelled`. A reported outcome is mandatory for `completed`.

## Assessment and vehicle-profile extension

| Entity | Purpose | Important links |
|---|---|---|
| `assessment_settings` | Current shared demonstration configuration (singleton). | Fixed rules plus editable assessment time/maximum observation age. |
| `configuration_history` | Configuration JSON and actual save timestamp. | Retains settings used in demonstration runs. |
| `vehicle_details` | Model year, fuel, transmission, engine capacity (cc), colour, purchase/service dates and service mileage (km), photo path/caption. | One record per vehicle. |
| `vehicle_equipment` | Recorded equipment labels. | Vehicle/name composite key. |
| `odometer_readings` | Non-negative kilometres, recorded timestamp and source. | Multiple entries per vehicle; latest by timestamp is displayed. |
| `vehicle_tyres` | One record per wheel: brand/model, size, season, four-digit DOT week/year, installation date/km, measured pressure (bar)/tread (mm), measurement timestamp, last rotation date. | Vehicle/position composite key; missing tyres are not fabricated. |
| `demo_extensions` | Identifiers of applied synthetic seed extensions. | Prevents repeating owner-history insertion across restarts. |

`Warning.current` and response `active` flags are derived for the selected assessment time. A rule warning is current only when it matches a triggered rule and the selected supporting observation. A pre-entered simulated forecast is visible as current after its input timestamp; forecast expiry modelling is not implemented. Historical warning rows and action links are not deleted or silently resolved.
